# EZEHR.Tools CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `ezehr-tools` a CLI built for manual testing, not just for the demo. It should reach every network call
as any party, take patients by a name you can remember, explain itself through `--help` at every level, and reject
typos instead of ignoring them.

**Architecture:** Spectre.Console.Cli replaces the hand-rolled `args[0]` switch and `CommandLine.Option`. Each leaf
command is a small `AsyncCommand<Settings>` class. The network and CA work each command does moves into static
`Calls/` classes, which the commands and `demo stage` share. All output goes through `AnsiConsole`, so tests can
capture it.

**Tech Stack:** .NET 11, Spectre.Console.Cli and Spectre.Console.Testing (latest stable; this plan was written against
the 0.50 API: check `ExecuteAsync`'s signature and `SetExceptionHandler`'s delegate against the installed version),
xUnit, the existing Testcontainers SQL fixture (`EZEHR.Tests/Data/SqlServer.cs`).

**Spec:** none separate. The user handed over the design ("however you see fit"), so the decisions are in the
**Design** section below. Read `docs/direction.md` for why realistic org behavior is what manual testing checks.

## Design

### Why

Manual testing today means replaying `stage`, or knowing which internal static method a scenario lives in. Concretely:
- **Typos are silent.** `CommandLine.Option` looks a flag up by position, so `--clinican` is ignored.
- **Patients are GUIDs.** The only lookup is Sam, through `demo status`.
- **Most calls are locked inside scenarios.** You can't read the full record as Lakeside, ask for medications as
  Kidney Check outside `stage`, push your own or a badly signed record, or use the audit's `since`, `until`,
  `patientId` and `limit` filters.
- **Help is one usage blob per command**, and the copies drift.
- **Nothing says where the tools point.**
- **`scripts/local.sh` still holds** patient lookup and SQL access, even though its header says the tools replaced it.

### Approaches

| Approach | Trade-off |
|---|---|
| **Spectre.Console.Cli (chosen)** | Typed settings, help with examples at every level, unknown options rejected, `Validate()` hooks, and the same library renders tables and color (respecting `NO_COLOR` and redirection). One new dependency, and its API changes between 0.x versions. |
| System.CommandLine 2.0 | Microsoft's, with stable parsing. No rendering, so tables and color stay hand-rolled. Help can't show examples. |
| Keep the hand-rolled parser, add shared help | Cheapest. Still needs an unknown-flag check written by hand in every command, and help still drifts. |

### Command tree

Each group's description says **who is acting** and **what it needs** (a certificate in `.pki/`, or the database).
This matches the stage's "actor" framing and direction.md's test: an organization acts through its own system.

```
ezehr-tools
├─ env                                   where the tools point, and what they hold
├─ org list                              the organizations the tools know, with certificate and seed status
├─ certs                                 issue certificates into .pki/ (the CA only; EZEHR isn't called)
│  ├─ issue          [ca options]        every demo organization, plus anchors.pem and intermediates.pem
│  ├─ platform       [ca options]        the platform operator's certificate, and the pin to set on the server
│  ├─ provider <slug> [ca options]       a new provider's certificate; EZEHR doesn't know it yet
│  ├─ app <slug>     [ca options]        a new app's certificate; EZEHR doesn't know it yet
│  └─ broker                             the broker's self-signed certificate
├─ platform                              the operator, with .pki/platform.pfx
│  ├─ register-provider <slug> --name
│  ├─ register-app <slug> --name --scope --description
│  ├─ onboard-provider <slug> --name [--invite <chart>] [ca options]   certs provider + register-provider (+ invite)
│  └─ onboard-app <slug> --name --scope --description [ca options]    certs app + register-app
├─ provider                              a provider's EHR system, with .pki/<provider>.pfx
│  ├─ invite <provider> <chart>
│  ├─ push <provider> <chart> [--file <path>] [--sign-as <identity>] [--corrupt-signature]
│  ├─ launch <provider> <chart> --clinician <object id> [--encounter <id>]
│  ├─ audit <provider> [--clinician <uri>] [--chart <chart>] [--patient <patient>] [--since] [--until] [--limit]
│  └─ clinicians <provider>
├─ app                                   the example apps, each with its own certificate
│  ├─ kidney-check <patient>
│  └─ medication-check <patient>
├─ network
│  └─ read <patient> <record> --as <identity> [--purpose <p>] [--expect <outcome>] [--raw]
├─ patient                               backstage: the database, never the network
│  ├─ find <patient>                     prints the EZEHR patient id only, for $(...)
│  ├─ list
│  └─ status <patient>
├─ db
│  └─ query "<sql>"                      backstage
└─ demo                                  the recorded demo
   ├─ reset [--yes]
   ├─ tamper
   └─ stage [--from <n>] [--list] [ca options]
```

**Shared argument forms.** These are parsed by type converters, so a bad value is a usage error:
- `<patient>`: an EZEHR patient id (GUID); `sam`; or `<provider>:<chart>`, for example `lakeside:LUC-20417`. Only
  the GUID form works without the database.
- `<identity>` (whose certificate the call presents): `none`; `broker` (`.pki/broker.pfx`, self-signed); any
  organization slug the tools know (`.pki/<slug>.pfx`, including `platform`); or a path ending in `.pfx`.
- `<chart>`: the provider's own patient id, for example `LUC-20417`. The code calls it `providerPatientId`; the
  CLI says "chart", as the stage text already does.
- `<record>`: `egfr-labs`, `medications` or `full-record`, mapped to `read-<record>`.
- `<outcome>` for `--expect`: `ok`, an HTTP status (`403`), or a `DenyReason` name (`ScopeDenied`). The exit code is
  0 when the outcome matches and 1 when it doesn't. That turns a manual check into a one-liner that can be rerun.
- `[ca options]`: `--ca local|ezca` (default `local`), `--key ec|rsa` (default `ec`), `--ca-id`, `--template-id`.
- Every command that calls the network takes `--base-url <url>` (default `EZEHR_BASE_URL`, else
  `https://localhost:7189`).

**Old → new.** There are no aliases, since only the team uses these commands. Docs and scripts get updated instead.

| Old | New |
|---|---|
| `certs issue [--ca …]` | `certs issue [--ca …]` |
| `certs issue --platform` | `certs platform` |
| `certs issue --provider <s> --name N [--invite C]` | `platform onboard-provider <s> --name N [--invite C]` |
| `certs issue --app <s> --name N --scope S --description D` | `platform onboard-app <s> --name N --scope S --description D` |
| `certs broker` | `certs broker` |
| `provider invite\|push\|launch\|clinicians …` | same |
| `provider audit <p> [--patient <chart>]` | `provider audit <p> [--chart <chart>]` |
| `kidney-check run <id>` | `app kidney-check <patient>` |
| `medication-check run <id>` | `app medication-check <patient>` |
| `broker request <id> --cert none\|self` | `network read <patient> full-record --as none\|broker --purpose treatment` |
| `stage …` | `demo stage …` |
| `demo status` | `patient status sam` |
| `demo reset`, `demo tamper` | same |

**Non-goals.** The CLI won't drive the patient's browser steps (enrollment, share codes, grants, emergency access).
They need a passkey, and writing grants straight to the database would skip the very thing being tested. It also
won't add aliases for old syntax, or a `--json` mode beyond `network read --raw`.

## Global Constraints

- Follow `docs/style-guide.md`: no `var`, block bodies only, file-scoped namespaces, `Id` not `ID`, descriptive
  names, and `dotnet csharpier format .` (`printWidth: 100`) before every commit.
- All tool output goes through `AnsiConsole`. `Console.Write*` is gone. The only exception is stage's key reading
  (`Console.ReadKey`, `Console.In`).
- Text from the server or from files is never parsed as markup. Use `MarkupLineInterpolated`, `Markup.Escape` or
  `new Text(...)`.
- Exit codes: `0` success; `1` the work failed or the server refused unexpectedly; `2` a usage error (parse or
  `Validate()`).
- Expected failures throw `ToolException(message)`: a missing env var, a missing `.pfx`, an unknown patient, an
  unreachable server. The exception handler prints the message in red and returns 1. No stack trace.
- Help:
  - Every leaf command has `.WithDescription(...)`: one line, at most 72 characters, starting with a verb, with no
    trailing period.
  - Every leaf has at least one `.WithExample(...)`, using demo values (`lakeside`, `LUC-20417`, `sam`).
  - Every branch description names who acts and what it needs.
  - Every argument and option has `[Description]`, and defaults are shown with `[DefaultValue]`.
- Argument placeholders are `<provider>`, `<chart>`, `<patient>`, `<slug>`, `<identity>`, `<record>`. Options are
  kebab-case long names only; `-h` is the one short form.
- Environment variables: `EZEHR_BASE_URL` (default `https://localhost:7189`), `AZURE_SQL_CONNECTIONSTRING`,
  `EZEHR_CLINICIAN_OBJECT_ID`, and new `EZEHR_PKI_DIRECTORY` (default `<repo root>/.pki`).
- Each network call lives in exactly one static method under `EZEHR.Tools/Calls/`. Commands and stage both call it.
- Settings properties are `{ get; init; }`, or `{ get; set; }` if the installed Spectre version won't bind `init`.
- Tools tests live in `EZEHR.Tests/Tools/`, in one xUnit collection with parallelization disabled, because
  `AnsiConsole.Console` and environment variables are process-wide.

## Review Focus

1. **Server text containing `[` or `]`,** such as JSON arrays in error bodies. It must print literally, not throw a
   markup exception. Task 1, `NetworkLogTests`.
2. **A server that doesn't answer** (stopped, or a wrong `--base-url`). Expect one red line naming the URL and exit
   1, and stage offers retry. Task 5, `NetworkReadCommandTests.UnreachableServerSaysWhichUrl`.
3. **`sam` or `<provider>:<chart>` with no database configured.** Expect one line naming
   `AZURE_SQL_CONNECTIONSTRING` and the env scripts. The GUID form must still work. Task 2,
   `PatientReferenceTests.NamedPatientWithoutDatabaseSaysHowToSetIt`.
4. **An identity whose `.pfx` is missing.** Expect one line naming the `certs` command that makes it, not a
   `FileNotFoundException` trace. Task 2, `IdentityReferenceTests.MissingPfxNamesTheCertsCommand`.
5. **The scripted stage rehearsal** (`demo stage < keys.txt`, stdin redirected). It must still read one key per line,
   and stop at the end of the input. Task 6, `StageKeysTests`.
